# Prompt Input 历史与光标导航设计

## 文档状态

- 日期：2026-07-11
- 状态：已实施（2026-07-11）

## 背景

Prompt Input 同时承担多行文本编辑、历史 Prompt 切换和 `/` 指令候选导航。
这些能力会共同占用方向键，因此需要明确不同状态下的按键优先级，避免一次按键同时被
解释成光标移动和历史切换。

当前实现已经支持：

- `↑` / `↓` 连续切换历史 Prompt；
- `←` / `→` 移动光标；
- `Ctrl+A` / `Ctrl+E` 按逻辑行移动，并可重复跨行；
- `Ctrl+U` 删除当前光标到行首的内容，并在行首时与上一行合并；
- 多行文本粘贴；
- `/` 指令候选出现时用 `↑` / `↓` 切换候选。

实施前缺少的核心规则是：进入历史以后，光标移动或编辑应当如何影响后续的历史切换。
该规则现已由 Prompt Input 的 history navigation 状态实现：纯光标移动暂停连续浏览但保留
历史位置，文本修改结束历史会话，方向键先处理候选列表和多行光标边界，再切换历史。

## 目标

- `/` 指令候选、历史浏览和普通编辑之间有明确且稳定的按键优先级。
- 支持多行 Prompt 内的垂直光标移动。
- 在第一行和最后一行使用 `↑` / `↓` 时，先把光标吸附到对应的行边界，再切换历史。
- 支持连续使用 `↑` / `↓` 浏览历史。
- 历史浏览期间，纯光标移动只暂停连续切换，并保留当前历史位置。
- 暂停后到达行首或行尾时，可以从当前历史位置继续向前或向后切换。
- 只有文本发生修改时才结束历史会话；修改后的内容成为普通草稿，不再恢复旧草稿。
- 从历史返回草稿时，准确恢复草稿文本和光标位置。
- 初期按逻辑行处理垂直移动，不在本次设计中解决超长文本和终端折行。

## 非目标

- 不处理超长 Prompt 的滚动、裁剪或分页显示。
- 不按终端视觉折行计算 `↑` / `↓` 的目标位置。
- 不增加历史搜索、历史持久化或历史条目编辑能力。
- 不改变 `/` 指令候选本身的过滤和补全逻辑。
- 不改变 `Ctrl+A`、`Ctrl+E` 和 `Ctrl+U` 已经确定的行为。

## 设计原则

### 1. 按键只能由当前最高优先级状态处理

优先级从高到低为：

1. `/` 指令候选；
2. 连续历史浏览；
3. 普通文本编辑。

一个按键一旦被更高优先级状态处理，就不再传递给下一层。

### 2. 历史位置与连续切换分开维护

历史浏览不是附着在文本上的永久索引，而是一段连续的交互会话。会话开始时保存当前
草稿和当前历史位置。连续按 `↑` / `↓` 时直接切换历史；一旦用户移动光标，只暂停这种
连续切换，历史位置和原草稿仍然保留。

暂停后，`↑` / `↓` 重新按普通光标规则移动。到达第一行行首或最后一行行尾后，再按
同方向键，就从保留的历史位置继续切换。只有文本被修改时，历史位置和原草稿才会一起
丢弃。

### 3. 根据实际变化暂停或结束历史

状态变化以编辑器是否真的发生变化为准，而不是仅判断按键名称。

例如：

- `←` 确实让光标向左移动：暂停连续切换，但保留历史位置；
- 光标已经在全文开头，再按 `←`：不产生变化，继续保持连续切换；
- `Ctrl+U` 确实删除了文本或合并了行：结束历史会话并丢弃历史位置；
- 空文本上按 `Ctrl+U`：不产生变化，不结束历史会话。

这条规则可以避免无效按键意外改变状态，也能让状态变化与用户实际看到的结果一致。

## 状态模型

Prompt Input 在交互上分为三个状态。

### `/` 指令候选状态

当候选列表可见时：

- `↑` / `↓` 只切换候选；
- 不移动文本光标；
- 不进入或切换历史；
- 信息行保持隐藏，沿用现有行为。

候选列表关闭后，再根据当时是否存在历史浏览会话进入对应状态。

### 连续历史浏览状态

建议将导航状态调整为：

```ts
type HistoryNavigation = {
  index: number;
  originalDraft: LineEditorState;
  browsing: boolean;
};
```

字段含义：

- `index`：当前显示的历史条目索引；
- `originalDraft`：进入历史前的完整编辑器状态，包括文本和光标位置。
- `browsing`：是否处于连续历史切换状态；纯光标移动后设为 `false`，但不删除整个
  `HistoryNavigation`。

这里不应只保存草稿字符串。否则从最新历史继续按 `↓` 返回草稿时，只能把光标放到
文本末尾，无法恢复用户进入历史前的光标位置。

### 普通编辑与历史定位暂停状态

不存在历史导航状态，或者历史导航存在但 `browsing` 为 `false` 时，Prompt Input 都按
普通多行编辑器处理方向键。区别是后者仍保留当前历史位置，到达边界后可以继续切换。
此时：

- 水平移动、行首行尾移动和删除操作沿用现有逻辑；
- `↑` / `↓` 优先尝试多行光标移动；
- 在第一行按 `↑` 时，先移动到行首；已经位于行首时才请求切换到上一条历史；
- 在最后一行按 `↓` 时，先移动到行尾；已经位于行尾时才请求切换到下一条历史；
- 没有历史定位的普通草稿不存在下一条历史，因此在全文末尾按 `↓` 保持不变。

## 按键处理规则

| 当前状态 | 按键 | 行为 |
| --- | --- | --- |
| `/` 指令候选可见 | `↑` / `↓` | 切换候选 |
| 连续历史浏览 | `↑` | 切换到更早的历史条目 |
| 连续历史浏览 | `↓` | 切换到更新的历史条目；越过最新条目时恢复原草稿 |
| 连续历史浏览 | 有效光标移动 | 执行移动，暂停连续切换，但保留历史位置和原草稿 |
| 连续历史浏览 | 有效文本修改 | 执行修改，结束历史会话并丢弃历史位置和原草稿 |
| 历史定位暂停 | `↑` / `↓` | 先按普通光标规则移动；到达对应边界后，从保留的历史位置继续切换 |
| 普通编辑 | `↑` | 优先向上一逻辑行移动；在第一行时先移动到行首，已经位于行首时切换到上一条历史 |
| 普通编辑 | `↓` | 优先向下一逻辑行移动；在最后一行时先移动到行尾，已经位于行尾时切换到下一条历史；没有下一条时保持不变 |
| 普通编辑 | 其他编辑键 | 按编辑器现有规则处理 |

## 普通编辑中的垂直光标移动

### 逻辑行

本阶段以文本中的换行符划分逻辑行。终端宽度导致的视觉折行不算新的一行。

例如，某一段很长的文本虽然在终端中显示成三行，只要中间没有换行符，仍然按一个
逻辑行处理。

### 目标列

连续垂直移动应记录一个 `preferredColumn`：

1. 第一次按 `↑` 或 `↓` 时，记录当前光标在逻辑行内的列位置；
2. 目标行足够长时，移动到相同列；
3. 目标行较短时，移动到目标行末尾；
4. 继续垂直移动时仍使用原始 `preferredColumn`，而不是被短行截断后的当前列；
5. 发生水平光标移动或文本修改后，清除 `preferredColumn`。

示例：光标从第 10 列上移到一个只有 4 列的短行时停在第 4 列；再次上移到长行时，
应回到第 10 列。

### 第一行和最后一行的边界处理

普通编辑状态下，`↑` 按以下顺序处理：

1. 如果存在上一逻辑行，向上一行移动；
2. 如果已经位于第一逻辑行，但光标不在该行行首，移动到该行行首；
3. 如果已经位于第一逻辑行行首，切换到上一条历史；如果尚未开始历史浏览，上一条
   指最新一条历史，并由此建立新的历史浏览会话。

普通编辑状态下，`↓` 按以下顺序处理：

1. 如果存在下一逻辑行，向下一行移动；
2. 如果已经位于最后一逻辑行，但光标不在该行行尾，移动到该行行尾；
3. 如果已经位于最后一逻辑行行尾，切换到下一条历史；当前已经是普通草稿或不存在
   更靠后的历史时，保持不变。

这是一组两段式边界操作。第一次按键负责把光标吸附到方向对应的边界，只有光标本来
就在边界上时，同方向按键才交给历史导航。这样可以避免光标位于第一行或最后一行中间
时，一次按键就意外替换当前 Prompt。

对于单行 Prompt，这组规则同样成立：光标在中间时，`↑` 先到行首、`↓` 先到行尾；
到达对应边界后，再次按同方向键才尝试切换历史。

这里的“下一条历史”沿用连续历史浏览的顺序：如果当前是某条历史，则进入更新的一条；
如果当前是最新历史，则恢复进入历史前的 `originalDraft`。历史会话已经被其他有效光标
移动暂停后，仍然保留“下一条”的位置；只有文本被修改后才丢弃该位置，之后按 `↓`
不得恢复旧草稿。

## 连续历史浏览

### 开始浏览

满足历史进入条件并按下 `↑` 时：

1. 保存当前完整 `LineEditorState` 为 `originalDraft`；
2. 显示最新一条历史 Prompt；
3. 将历史条目的光标放在全文末尾；
4. 建立新的历史导航状态。

如果历史为空，按键不产生变化，也不建立导航状态。

### 浏览更早和更新的历史

- `↑` 显示更早一条历史；到达最早一条后继续按 `↑`，保持不变；
- `↓` 显示更新一条历史；
- 在最新一条历史上继续按 `↓`，恢复 `originalDraft`，并退出历史浏览。

每次切换到一条历史 Prompt 后，光标都放在该条目的全文末尾。

### 暂停浏览与结束会话

历史浏览期间，以下纯光标操作只要造成实际移动，就执行操作并将 `browsing` 设为
`false`，但保留 `index` 和 `originalDraft`：

- `←` / `→`；
- `Ctrl+A` / `Ctrl+E`；
- 在暂停状态下由 `↑` / `↓` 造成的逻辑行移动或行首行尾吸附；
- 未来增加的任何纯光标移动。

暂停以后：

- 当前内容仍然对应原来的历史条目；
- `↑` / `↓` 先移动光标；
- 到达第一行行首后再按 `↑`，从当前 `index` 切换到更早的历史；
- 到达最后一行行尾后再按 `↓`，从当前 `index` 切换到更新的历史；
- 成功切换历史后，将 `browsing` 重新设为 `true`。

以下操作只要真正修改文本，就结束历史会话：

- 普通字符输入；
- 多行粘贴；
- `Backspace`、`Delete`、`Ctrl+D`、`Ctrl+U`；
- Tab 补全或其他会修改文本的操作；
- 未来增加的任何文本修改。

结束以后：

- 当前历史内容连同用户的修改一起成为普通草稿；
- 丢弃旧的历史索引；
- 丢弃进入历史前保存的 `originalDraft`；
- 后续 `↓` 不得恢复旧草稿或覆盖当前内容；

如果之后再次满足历史进入条件并按 `↑`，将从最新一条历史开始一段全新的浏览会话，
而不是从修改前的索引继续。

## 典型交互示例

假设历史从旧到新为 `H1`、`H2`、`H3`，进入历史前的草稿为 `D`。

### 连续浏览并返回草稿

```text
D --↑--> H3 --↑--> H2 --↑--> H1
H1 --↓--> H2 --↓--> H3 --↓--> D
```

返回 `D` 时，同时恢复进入历史前的光标位置。

### 移动光标后暂停并继续

```text
D --↑--> H3 --↑--> H2 --←--> H2（历史定位暂停）
```

`←` 产生有效移动后，连续切换暂停，但仍保留 `H2` 的历史位置：

```text
H2 中间 --↑--> H2 行首 --↑--> H1
H2 中间 --↓--> H2 行尾 --↓--> H3
```

这两个方向都从 `H2` 继续，不会重新从最新历史开始。

### 修改历史条目后结束会话

```text
D --↑--> H3 --输入文本--> H3 edited
```

此时 `H3 edited` 是普通草稿。按 `↓` 不得恢复 `D`，否则会丢失用户刚才的修改。

### 多行编辑中的 `↑`

```text
first line
second |line
```

光标位于第二行时，`↑` 先移动到第一行的对应列，不进入历史。如果落点不在第一行
行首，再按一次 `↑` 只移动到行首；只有光标已经位于第一行行首时，下一次 `↑` 才开始
历史浏览。

### 第一行和最后一行的两段式操作

```text
first l|ine
second line
```

第一次按 `↑` 后光标移动到第一行行首；再次按 `↑` 才切换到上一条历史：

```text
|first line --↑--> 上一条历史
```

向下方向对称处理：

```text
first line
second |line --↓--> second line| --↓--> 下一条历史
```

如果当前已经是普通草稿，没有可切换的下一条历史，最后一次 `↓` 保持不变。

## 与 Codex CLI 行为的关系

Codex CLI 的实现同样先判断历史导航是否应当处理 `↑` / `↓`，否则把按键交给文本框
进行多行光标移动。它对非空文本使用“光标处于全文边界，并且当前文本仍与最后一次
历史文本一致”的门控条件。

参考：

- [Codex history navigation gate](https://github.com/openai/codex/blob/rust-v0.144.1/codex-rs/tui/src/bottom_pane/chat_composer_history.rs#L333-L361)
- [Codex composer Up/Down routing](https://github.com/openai/codex/blob/rust-v0.144.1/codex-rs/tui/src/bottom_pane/chat_composer.rs#L3180-L3207)

Tinker 在此基础上显式区分“光标移动”和“文本修改”：光标移动只暂停连续切换并保留
历史位置，文本修改才丢弃历史导航状态。这样既能从移动后的光标位置继续浏览历史，也
能避免修改后的历史文本被旧草稿恢复逻辑覆盖。

## 建议的实现边界

### `line-editor.ts`

负责纯编辑器能力：

- 根据逻辑行计算 `moveUp` 和 `moveDown`；
- 维护或接收 `preferredColumn`；
- 返回移动后的文本和光标状态；
- 不感知 Prompt 历史和 `/` 指令候选。

### `prompt-input.tsx`

负责交互状态机：

- 按优先级路由 `↑` / `↓`；
- 开始、推进、暂停、恢复和结束历史会话；
- 分别比较文本与光标变化：光标变化暂停连续切换，文本变化结束历史会话；
- 进入历史时保存完整 `LineEditorState`；
- 纯光标移动时保留 `index` 和 `originalDraft`；
- 文本修改时立即丢弃旧的 `index` 和 `originalDraft`。

建议把“应用编辑器变更”和“根据变化暂停或结束历史”收敛到一个统一入口，避免某个
按键新增处理逻辑后忘记更新历史状态。

## 测试范围

至少覆盖以下行为：

- 空输入按 `↑` 进入最新历史；
- 单行非空输入在中间位置按 `↑` 先移动到行首，再按 `↑` 才进入历史；
- 单行非空输入在中间位置按 `↓` 先移动到行尾，再按 `↓` 才请求下一条历史；
- 多行输入位于第一行中间时，按 `↑` 移动到第一行行首，不立即进入历史；
- 多行输入位于最后一行中间时，按 `↓` 移动到最后一行行尾，不立即切换历史；
- 第一行行首按 `↑` 切换到上一条历史；
- 最后一行行尾按 `↓` 切换到下一条历史，没有下一条时保持不变；
- 多行输入按 `↑` / `↓` 先进行逻辑行间移动；
- 连续垂直移动跨越长短行时保留 `preferredColumn`；
- 历史浏览可连续向前、向后切换；
- 越过最新历史时恢复原草稿及原光标位置；
- 在最早历史继续按 `↑` 保持不变；
- 历史中有效的 `←` / `→`、`Ctrl+A` / `Ctrl+E` 会暂停连续浏览并保留历史位置；
- 历史中无效的光标移动不会暂停连续浏览；
- 光标移动后，先按 `↑` 到行首，再按 `↑` 会从当前条目切到更早的历史；
- 光标移动后，先按 `↓` 到行尾，再按 `↓` 会从当前条目切到更新的历史；
- 历史中输入、粘贴和删除会结束历史会话；
- 文本修改后按 `↓` 不会恢复旧草稿；
- 文本修改后再次进入历史会从最新条目开始；
- `/` 指令候选可见时，`↑` / `↓` 只切换候选；
- 多行历史条目进入后光标位于全文末尾。

## 已实施的交互结论

- 采用“候选列表、连续历史浏览、普通编辑”三个交互状态；
- 纯光标移动暂停连续历史浏览，但保留当前历史位置和原草稿；
- 到达行首或行尾后，可以从保留的位置继续向前或向后切换历史；
- 文本修改才结束历史会话，修改后的内容成为普通草稿；
- 文本修改后再次进入历史时从最新条目开始；
- 多行垂直移动本阶段按逻辑行实现，并保留目标列；
- 第一行的 `↑` 和最后一行的 `↓` 采用“先到行边界，再切历史”的两段式操作；
- 原草稿保存完整编辑器状态，以准确恢复文本和光标。

后续调整应同步修改上述状态切换规则、示例、实现和测试。
