# TUI 文件引用设计

## 背景

Prompt Input 已经支持 `/` 指令候选，但还不能在编写 Prompt 时查找并插入工作区
文件路径。这个能力只属于交互式 TUI：它帮助用户输入路径，不改变提交给模型的消息
结构，也不读取或附加文件内容。

实现参考 Codex CLI 的旧版文件专用 popup 和当前 file-search 搜索层，并按 Tinker 的
范围做简化：只搜索文件，不聚合技能、插件、目录或其他 mention 类型。

## 目标

- 当 `@` 位于输入开头或前一个字符是空白字符时，激活文件候选。
- 裸 `@` 立即列举工作区文件，初始候选按目录深度从浅到深排列。
- 输入 `@` 后面的查询时，对工作区相对路径做不区分大小写的模糊过滤。
- 使用 `↑` / `↓` 选择候选，使用 `Enter` 或 `Tab` 插入候选。
- 选中后移除 `@` 和查询文本，只插入未加引号的工作区相对路径。
- 至少排除 `node_modules`，同时排除 `.git` 和 `.tinker` 内部目录。
- 遵循 `.gitignore`，包括未被忽略的隐藏文件，不跟随符号链接目录。
- 文件候选打开时，其键盘交互优先于历史导航和普通编辑。

## 非目标

- 不把文件内容自动添加进模型上下文。
- 不引入结构化 mention、附件或新的消息协议。
- 不搜索目录、技能、插件、MCP 资源或其他聚合内容。
- 不为带空格的路径添加引号或转义。
- 不改变 one-shot CLI 的输入语义。

## 激活与 token 规则

文件 token 由 `@` 开始，并在下一个空白字符处结束。`@` 必须位于输入开头，或者它的
前一个字符必须是空白字符，因此 `name@example.com` 不会触发候选。

光标位于 token 内部或紧跟 token 末尾时，候选保持激活；在 token 后输入空白字符后
关闭。历史浏览条目沿用现有候选抑制规则，不会仅因条目中包含 `@` 就自动打开候选；
用户修改文本并回到普通草稿状态后，再按新的 token 状态激活。

`Esc` 关闭当前候选；文本再次发生变化后，可以按新的 token 状态重新激活。

## 文件枚举

首次进入一次文件候选交互时，异步运行 `rg --files`，工作目录固定为当前
`workspaceRoot`。枚举规则为：

- 使用工作区相对路径；
- 启用隐藏文件；
- 使用 ripgrep 的默认 ignore 处理，因此在 Git 工作区中遵循 `.gitignore`；
- 显式排除任意层级的 `node_modules`、`.git` 和 `.tinker`；
- 只返回文件，不跟随符号链接目录。

枚举失败时在 popup 中直接显示错误，不静默降级到另一套语义不同的遍历方式。

裸 `@` 的初始排序先比较路径深度，再按不区分大小写的路径字典序排列。这样根目录
文件会优先出现，然后逐层进入子目录。

## 模糊过滤

查询对完整相对路径做不区分大小写的子序列匹配。排序优先考虑：

1. 文件名部分能够匹配；
2. 连续字符和路径、单词边界处的匹配；
3. 更少的跳跃字符；
4. 更浅、更短的路径；
5. 稳定的路径字典序。

popup 最多显示 8 条候选。高亮查询实际匹配到的字符，但高亮不影响排序或插入值。

## 键盘优先级与提交

交互优先级从高到低为：

1. 文件候选；
2. `/` 指令候选；
3. 连续历史浏览；
4. 普通文本编辑。

文件候选可见且存在匹配时：

- `↑` / `↓` 循环选择；
- `Enter` 或 `Tab` 用候选替换当前完整 `@查询` token；
- `Esc` 关闭候选且保留输入。

替换结果不带 `@`、引号或转义。若 token 后已有一个普通空白分隔符，则复用它；
否则在路径后补一个空格并把光标放到分隔符之后，方便继续输入。没有可选结果时，
`Enter` 保持现有提交行为，`Tab` 只关闭候选。

## 测试边界

- token 识别覆盖输入开头、前置空白、全角空白、邮箱样式和光标位置。
- 文件排序覆盖裸 `@` 的浅层优先和查询后的稳定模糊排序。
- 路径替换覆盖移除 `@`、不加引号、复用已有空格和 Unicode 光标索引。
- 文件枚举使用临时 Git 工作区验证 ignore、隐藏文件和显式排除目录。
- TUI 测试覆盖加载、导航、插入、关闭，以及文件候选对 slash/history 的优先级。
