本文记录一次关于 MemorySearch 相关度阈值的设计探讨，供后续回顾。不是实施承诺。

## 一、问题

`MemorySearch` 固定返回至多 5 条记忆（`MEMORY_SEARCH_LIMIT = 5`）。只要候选存在，
无论相关度高低都会返回。当记忆库中其实没有与当前意图相关的内容时，模型仍会拿到
5 条噪声记忆，可能误导后续行为。

设想：设立相关度阈值，低于阈值的结果不返回，或者在 observation 中明确提示
"相关度过低，可换关键词重试或停止检索"。

## 二、现状链路事实（分析依据）

```text
向量召回：归一化 embedding 的余弦相似度，取 top-20 候选
关键词召回：FTS5 BM25（列权重 10.0/1.0），取 top-20 候选
融合：RRF（k=60），score = Σ 1/(60+rank)
返回：融合后无条件切 top-5
```

关键事实：**最终融合的 RRF 分数是纯排名分，不携带绝对相关度信息**。
余弦 0.35 的第 1 名与余弦 0.92 的第 1 名，RRF 贡献完全相同（1/61）。
因此"给返回结果的分数设阈值"在 RRF 之下不成立；阈值只能加在召回阶段、
融合之前。

## 三、分路径评估

| 召回路径 | 能否设阈值 | 分析 |
| --- | --- | --- |
| 向量（余弦） | 可以，但阈值不可硬编码 | 余弦有界、语义可解释。但绝对阈值的校准是 embedding 模型相关的：有的模型把相似度挤在 0.7–0.9，有的分布很散。Tinker 的 embedding endpoint 由用户在 models.json 自配，固定阈值会在别的模型上失灵 |
| 关键词（BM25） | 不建议 | BM25 无界且随语料漂移，不可校准。且 FTS 命中本身自带相关性信号（词确实出现）；OR 语义下的弱匹配可靠 RRF 排名自然沉底 |

## 四、候选方案（若未来实施）

分两期，先拿数据再定阈值：

**第一期：观测（已于 2026-08-29 实施）**
- `MemorySearchDiagnostic` 新增 `vectorScores` 字段：向量召回候选的原始余弦
  top-10（按相关度降序，三位小数），写入既有诊断 JSONL。`scores` 字段仍是 RRF
  融合分，保持原语义不变
- 正常使用一段时间，依据真实分布选择阈值，而非拍脑袋

**第二期：向量余弦下限**
- 向量召回后、融合前过滤 `cosine < floor` 的候选；FTS 路径不动
- floor 必须**可配置**（models.json 的 `memory.embedding` 可选字段，或
  `TINKER_MEMORY_MIN_COSINE` 环境变量），默认值取自第一期数据，初始偏保守
  （约 0.25 量级）
- 过滤后为空时的 observation 文案是本设计的要点：明确告知模型"没有超过
  相关度下限的记忆，可换关键词重试或停止检索"。契约无需改动——keyword-only
  搜索无命中时本就可能返回少于 5 条

**附带收益**：被过滤的向量噪声候选不再参与 RRF，FTS-only 的有效匹配不会被
向量噪声稀释排名，混合检索质量可能略有提升。

**主要风险**：阈值偏高会挡掉"不完美但有用"的记忆，而这恰是记忆系统的常态。
因此可配置 + 保守默认值优于任何硬编码的激进阈值。

## 五、暂缓理由与复评信号

暂缓理由：当前记忆库规模小，top-5 经常被不相关候选填满，问题显眼；当记忆
积累到一定规模后，相关候选增多，噪声占比可能自然下降，阈值未必仍是痛点。

建议的复评信号（出现以下情况时回到本文）：

- 实践中频繁观察到模型被不相关记忆带偏（而非仅仅"返回了噪声但模型忽略了"）
- 诊断日志显示向量召回的余弦分布出现明显的"相关/不相关"双峰，阈值容易选取
- 记忆库规模增长到 top-5 仍稳定掺入噪声的程度
